Purpose: Stage 5 checks, packages and prepares provisional outputs for expert review.

What happens in this stage?

The output of the LLM tagging passes is checked for structural validity, taxonomy validity, consistency and review needs. Reviewer-facing files are then created so that human experts can inspect, correct and comment on candidate outputs.

QA checks

CheckWhy it matters
Required columns present Prevents broken downstream processing.
Valid taxonomy IDs Ensures the model has not invented labels.
Pass 1 / Pass 2 disagreement Identifies cases for adjudication or expert review.
Low confidence or uncertainty Ensures uncertain cases remain visible.
Review status assigned Separates plausible provisional rows from rows needing attention.
Provenance marked Prevents LLM output being mistaken for validated evidence.

Review workbook

The reviewer workbook should present candidate rows in a form that experts can check efficiently. It should preserve the original sentence, the sampled lemma, Pass 1, Pass 2 and Pass 3 decisions, confidence values, rationales and review flags.

Reviewer columnPurpose
expert_decisionAccept, change, uncertain, or reject.
expert_function_idCorrected function ID where needed.
expert_commentReason for change or uncertainty.
adjudication_requiredMarks cases needing a final human decision.

Checks and risks

  • Do not describe the dataset as validated until expert review and validation are complete.
  • Keep LLM-generated assignments marked as llm_judgment and provenance_tier = 4.
  • Keep ambiguous rows visible rather than smoothing them away.
  • Preserve disagreements between passes for audit.
  • Reviewer comments should be retained as part of the project record.
