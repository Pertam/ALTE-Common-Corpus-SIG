Reviewer Area

Practical guidance for expert reviewers checking provisional sentence-level function tags and vocabulary atlas candidate rows.

Purpose of reviewer work

The reviewer area explains how human experts should inspect, correct and comment on candidate outputs produced by the project workflow. Reviewers are not asked to approve the system automatically. Their role is to check whether the proposed labels, rationales and review flags are defensible.

The main reviewer task is to examine sentence-level function tags and, where relevant, concept-level vocabulary judgements. Reviewers should look for sense confusion, unsuitable taxonomy labels, overconfident classifications, cross-linguistic mismatch, register problems and cases where more evidence is needed.

What reviewers are reviewing

Review object What it contains Main reviewer question
Sentence-level function tag A sentence, sampled lemma, Pass 1 tag, Pass 2 validation and optional Pass 3 adjudication. Is the final function label the best description of what the whole sentence is doing?
Concept / sense row A concept label, sense definition, language-specific form, CEFR candidate level and rationale. Is the sense correctly separated and is the CEFR judgement plausible?
Cross-linguistic alignment Equivalent concept rows across languages. Are the language forms natural equivalents for the same sense, and are any level differences justified?
Review flags Confidence, uncertainty notes, disagreement between passes and review status. Has the system correctly identified rows that need human attention?

Core reviewer principle

Review the communicative function of the whole sentence, not just the topic of the sentence and not only the lemma that caused the sentence to be sampled.

Sentence Sampled lemma Good review focus Bad review focus
Could you send me the report by Friday? send The sentence performs a request for action. Only describing the meaning of send.
The company sent the report yesterday. send The sentence reports a past event. Assuming every sentence with send is a request.
Please send the form to the address below. send The sentence gives an instruction. Treating it as general workplace vocabulary only.

Recommended review decisions

Reviewers should use a small number of clear decision categories. The exact column names may vary by workbook, but the decision logic should remain consistent.

Decision Use when Reviewer action
accept The proposed function or CEFR judgement is defensible and no better alternative is apparent. Leave the proposed label unchanged and optionally add a brief comment.
change Another taxonomy label or CEFR judgement is clearly better. Enter the corrected label or level and explain the reason.
uncertain The row is ambiguous, context is insufficient, or more evidence is needed. Mark for further review and explain the uncertainty.
reject The row is unusable, malformed, not in the target language, or does not contain enough interpretable context. Mark as rejected and explain why it should not be used.

Suggested reviewer workbook columns

A reviewer workbook should preserve the machine-generated output but add separate columns for human decisions. This makes it possible to compare the original candidate output with expert review.

Column Purpose Example value
expert_decision Reviewer judgement on the candidate row. accept, change, uncertain, reject
expert_function_id Corrected function ID, if changed. use valid taxonomy ID
expert_function_label Corrected function label, if changed. requesting action
expert_receptive_cefr Corrected receptive CEFR level, where concept-level review is being done. A2, B1, B2
expert_productive_cefr Corrected productive CEFR level, where concept-level review is being done. Same as or higher than receptive CEFR.
expert_comment Short explanation of the decision. Sentence is an instruction, not a request.
adjudication_required Marks rows needing a second expert or final project decision. true or false

How to review a sentence-level function tag

Use the following sequence when checking a function-tagged sentence.

Step Reviewer question Possible action
1. Read the whole sentence What is the sentence doing communicatively? Ignore the sampled lemma at first and identify the sentence function.
2. Check the proposed function Does the proposed label match the whole sentence? Accept it if it is clearly defensible.
3. Compare alternatives Is another taxonomy label clearly better? Change only if the alternative is stronger.
4. Check ambiguity Could two functions reasonably apply? Mark uncertain or adjudication required.
5. Comment briefly Can another reviewer understand your decision? Add a short, explicit comment.

Examples of reviewer decisions

Sentence Candidate label Reviewer decision Reviewer comment
Could you send me the report by Friday? Requesting action accept The sentence politely asks the recipient to do something by a deadline.
The company sent the report yesterday. Requesting action change This reports a past event; it is not asking anyone to act.
Please send your completed form to the address below. Requesting action change This is better treated as an instruction in an administrative context.
You may send the form by email or post. Giving an instruction uncertain The sentence gives permission or options rather than a direct instruction; check taxonomy alternatives.

How to review a concept-level vocabulary row

Some review tasks will focus on vocabulary atlas rows rather than sentence function rows. In these cases, reviewers should focus on sense, naturalness, CEFR judgement and evidence.

Step Reviewer question Example issue
1. Check the sense Does this row represent one clear concept? bank financial institution should not be merged with river bank.
2. Check the language form Is this the natural way to express the concept in the target language? A literal translation may be grammatically possible but unnatural.
3. Check receptive level When could learners reasonably understand this item in context? A transparent cognate may be understood earlier than it can be produced.
4. Check productive level When could learners produce it accurately and appropriately? Case government, prepositions, reflexives or collocations may raise productive difficulty.
5. Check evidence Is the rationale supported by supplied evidence? Do not accept invented corpus counts or unsupported source claims.

Common issues reviewers should look for

Issue What it looks like Recommended response
Topic/function confusion The tag describes the subject matter rather than the communicative function. Change to the function of the whole sentence.
Lemma/function confusion The tag is based only on the sampled lemma. Re-read the whole sentence and retag accordingly.
Over-specific tag The model selects a very narrow label when a broader label fits better. Change if the narrower label is not justified.
Over-general tag The model selects a vague label despite a clear specific function. Change to the best available specific taxonomy label.
Register mismatch A formal, administrative or technical use is treated as neutral everyday language. Add a comment and mark for review if this affects CEFR judgement.
Polysemy error Two senses of the same form are treated as one item. Recommend sense split or separate concept IDs.
Cross-linguistic flattening Equivalent-looking forms are forced into the same level without justification. Preserve divergence and explain the likely reason.
Unsupported evidence The rationale claims a source level, corpus count or frequency rank that was not supplied. Remove or flag the unsupported claim.

Good reviewer comments

Reviewer comments should be short but specific. They should explain the reason for accepting, changing or marking a row as uncertain.

Weak comment Better comment
Wrong. This reports a completed past event; it is not a request or instruction.
Maybe B1. Receptive B1 is plausible, but productive use may be B2 because the target form requires a governed preposition.
Translation bad. The proposed equivalent is literal but unnatural for this sense; use the standard construction for applying for a job.
Check. Ambiguous between permission and instruction; needs adjudication against taxonomy guidance.

When to mark adjudication required

Use adjudication when a row needs a further decision by another expert or by the project team.

Mark adjudication required when... Example
Two taxonomy labels are both plausible. A sentence could be read as giving permission or giving an instruction.
The sense is unclear from the available context. A single sentence does not show which meaning of a polysemous word is intended.
The language equivalent appears unnatural or disputed. A literal equivalent is possible but not idiomatic.
The receptive/productive CEFR split is difficult to judge. The item is easy to understand but difficult to produce because of morphology or constructional pattern.
The row may reveal a taxonomy problem. No available function label seems to fit the sentence well.

Reviewer checklist

Check Done?
The whole sentence has been considered, not only the sampled lemma.
The selected function ID exists in the controlled taxonomy.
The function label matches the sentence-level communicative purpose.
Ambiguity or disagreement has been marked clearly.
Any corrected label has been entered in the expert columns.
The reviewer comment explains the decision clearly.
For concept-level rows, receptive CEFR is not higher than productive CEFR.
Unsupported evidence claims have been flagged.
