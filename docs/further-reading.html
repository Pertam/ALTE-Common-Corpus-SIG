Purpose of this page

This page provides a topic-based reading guide for the ALTE Common Corpus SIG project and the European CEFR Vocabulary Atlas pilot. It is designed for SIG members, reviewers, technical contributors and assessment or curriculum readers who want to understand the research areas behind the workflow.

The project sits at the intersection of several traditions: CEFR alignment, Reference Level Descriptions, vocabulary profiling, learner corpus research, corpus linguistics, language assessment, multilingual comparison and LLM-assisted classification. The sections below group suggested reading by topic and explain why each area matters for the project.

1. CEFR framework and descriptors

The CEFR provides the shared descriptive framework for language learning, teaching and assessment. For this project, the CEFR is important not only as a level scale, but also as a functional and communicative framework.

Resource Why it matters for this project How to use it Link
Common European Framework of Reference for Languages The foundational framework for describing language proficiency across A1-C2. Use as the broad reference point for level interpretation, communicative activities and language competence. Council of Europe CEFR page
CEFR Companion Volume Extends and updates the original CEFR descriptors, including mediation, online interaction and plurilingual/pluricultural competence. Use as the main descriptor source when interpreting communicative functions and modern CEFR constructs. CEFR Companion Volume resources
Searchable CEFR descriptors Allows readers to inspect CEFR descriptors by level, skill, activity and strategy. Use when checking whether a proposed function or language activity has a plausible CEFR anchor. CEFR descriptor resources
CEFR action-oriented approach Frames learners as social agents performing tasks in contexts. Use to justify why sentence-level communicative function matters, not just isolated vocabulary knowledge. CEFR key concepts

2. Reference Level Descriptions and language-specific CEFR content

Reference Level Descriptions are especially relevant because this project is multilingual. The CEFR is intentionally language-general, but vocabulary and grammar have to be specified separately for individual languages.

Resource Why it matters for this project How to use it Link
Reference Level Descriptions Provide language-specific specifications of forms, words, grammar and other content at CEFR levels. Use as a model for thinking about how a CEFR-aligned vocabulary atlas must work language by language. Council of Europe RLD page
RLD production guidance Explains principles for producing language-specific descriptions linked to the CEFR. Use when developing project governance for future validated vocabulary data. RLD guidance and resources
Threshold Level series Earlier language-specific CEFR-related work that influenced later functional and lexical descriptions. Use as historical background for functional-notional approaches and CEFR language specification. Threshold Level and RLD resources

Relevance for the Atlas: RLD work supports the idea that a cross-linguistic vocabulary resource should not simply translate an English list. It should identify concepts and senses, then describe how each language realises them.

3. ALTE, language testing and assessment quality

ALTE is relevant because the project has clear implications for language assessment: text selection, item writing, vocabulary load, comparability and validation.

Resource or topic Why it matters for this project How to use it Link
ALTE Provides a European professional context for multilingual language assessment and quality standards. Use as the organisational and assessment-quality context for the SIG work. ALTE website
ALTE resources Relevant for test development, quality management, validation and CEFR-related assessment practice. Use for background when discussing how Atlas data could support assessment development and review. ALTE resources
Relating examinations to the CEFR Relevant to any later attempt to connect vocabulary evidence with test specifications or exam levels. Use as background for alignment, standard setting and validation discussions. Council of Europe CEFR assessment resources
Assessment validity and comparability The project may help explain whether texts or items at the same CEFR level impose similar lexical demands. Use when discussing test fairness, construct representation and cross-language comparability. ALTE resources

4. Vocabulary profiling and CEFR lexical resources

Vocabulary profiling is central to the project. Existing CEFR vocabulary resources show how lexical information can support teaching, materials development and assessment, but they also show the need for sense-level and language-specific analysis.

Resource or topic Why it matters for this project How to use it Link
English Profile Major example of CEFR-informed language profiling for English. Use as a reference point for what a mature CEFR profiling project can look like. English Profile
English Vocabulary Profile Important because it works with vocabulary meanings, phrases and CEFR levels, not just word forms. Use as a comparator for sense-level vocabulary description and pedagogical sequencing. English Vocabulary Profile resources
English Grammar Profile Shows how learner evidence can be used to describe grammar development across CEFR levels. Use as a parallel example for feature-based CEFR profiling. English Grammar Profile
Sense-level vocabulary description Essential because the Atlas treats concept and sense as the unit of analysis. Use to justify splitting polysemous headwords and avoiding direct word-for-word translation. Project methodology: concept and sense principles

5. Corpus linguistics and corpus-derived vocabulary evidence

Corpus linguistics provides the evidence base for frequency, dispersion, examples and usage environments. For the Atlas, corpus evidence helps identify how vocabulary is actually used, but it does not by itself determine CEFR level.

Topic Why it matters for this project How to use it
Frequency Shows how often a lemma, form or expression occurs in the corpus. Use as supporting evidence, not as an automatic CEFR level.
Frequency per million Allows comparison across corpora or subcorpora of different sizes. Use when comparing languages or datasets with different token counts.
Dispersion Shows whether an item is spread across the corpus or concentrated in a narrow set of texts. Use to avoid overvaluing items that are frequent but topic-specific.
ARF Combines frequency and distribution evidence in a way that supports sampling. Use for pilot filtering and sampling decisions, not for direct CEFR classification.
Concordance analysis Shows examples of an item in real sentence contexts. Use to inspect sense, collocation, register and function environments.
Collocation and phraseology Many vocabulary items are learned and used as patterns rather than isolated words. Use when deciding whether an item is a lexical concept, multiword expression or construction.

Suggested reading areas: corpus linguistics introductions, frequency and dispersion measures, corpus-based lexicography, vocabulary profiling, collocation studies and learner corpus research.

6. Learner corpora and validation evidence

Learner corpora are important for future validation because they can show what learners actually produce at different CEFR levels. They are especially useful for distinguishing receptive plausibility from productive control.

Topic Why it matters for this project How to use it
Learner production evidence Shows which vocabulary, constructions and collocations learners can produce at different levels. Use in later validation of productive CEFR candidate levels.
Error patterns Shows where learners struggle with morphology, prepositions, collocation, register or word choice. Use to explain why productive CEFR may be higher than receptive CEFR.
Levelled learner corpora Provide evidence linked to assessed CEFR levels. Use carefully, considering task type, learner L1, assessment context and rating quality.
Cross-linguistic learner evidence Can reveal whether an item is especially difficult for learners with particular L1 backgrounds. Use as supplementary evidence, not as a universal level assignment.

7. LLM-assisted classification and AI-supported annotation

LLMs are used in the project as annotation and classification assistants, not as final authorities. The key methodological question is how to use LLMs in a controlled, auditable and reviewable way.

Topic Why it matters for this project How to use it
Prompt design The quality of function tagging depends heavily on clear instructions, controlled labels and examples. Use prompts that define the task, prohibit invented labels and require concise rationales.
Controlled output schemas Prevents free-text labels and makes outputs easier to validate automatically. Use JSON schemas and validate all function IDs against the taxonomy.
Multi-pass validation Reduces one-shot labelling and makes disagreement visible. Use Pass 1 for first labelling, Pass 2 for challenge, Pass 3 for adjudication.
Human-in-the-loop review LLM outputs need expert checking, especially for ambiguous or high-impact rows. Use confidence, disagreement and review flags to prioritise human review.
Classification evaluation Future versions may need F1, agreement, adjudication rates and error analysis. Use manually reviewed data as gold or silver-standard evaluation material.
Bias and overconfidence LLMs may overgeneralise, flatten cross-linguistic differences or sound more certain than evidence allows. Require uncertainty notes, confidence limits and expert review.

Suggested reading areas: LLM annotation, prompt engineering, structured outputs, human-in-the-loop NLP, model evaluation, automated CEFR classification and AI-assisted language assessment.

8. NLP and multilingual processing

The project depends on NLP processing before any LLM classification can happen. Tokenisation, lemmatisation and POS tagging affect the quality of downstream lemma statistics and sentence samples.

Topic Why it matters for this project How to use it
Sentence splitting Function tagging depends on having clean sentence units. Check language-specific sentence boundary issues, especially abbreviations and punctuation.
Tokenisation Token counts affect frequency and downstream processing. Use consistent tokenisation rules and record the tool used.
Lemmatisation Links inflected forms to a common lemma. Inspect errors in morphologically rich languages such as Czech and German.
POS tagging Content-word filtering depends on reliable POS labels. Review ambiguous cases where a form can function as noun, verb, adjective or adverb.
Multilingual NLP comparability Different language models and taggers may introduce different error profiles. Do not assume all language pipelines are equally accurate without checking samples.

9. Functional-notional language description

The function-tagging part of the project connects vocabulary with communicative purpose. This draws on the broader tradition of functional-notional language description and CEFR communicative activities.

Topic Why it matters for this project Example project relevance
Communicative functions Language items are used to perform actions such as requesting, explaining, comparing and evaluating. Sentence-level function tagging records what a sentence is doing, not just what topic it mentions.
Notions and concepts Learners need language to express concepts such as time, quantity, obligation, possibility and comparison. The Atlas can connect lexical concepts with functional environments.
Task-based use Vocabulary is learned and assessed through tasks, not only memorised lists. Assessment use cases include checking whether task input has suitable lexical and functional demands.
Register and situation The same concept may be expressed differently in informal, academic, technical or administrative contexts. Register should be recorded and considered in CEFR judgement.

10. Language assessment, text classification and vocabulary load

A major use case for the project is assessment support: checking vocabulary load, comparing text difficulty and supporting item-writing decisions.

Topic Why it matters for this project How to use it
Vocabulary load Texts can become harder because of vocabulary even when grammar or topic appears suitable. Use Atlas-style data to identify difficult concepts in reading or listening texts.
Text classification Texts may be profiled by likely CEFR vocabulary demand and communicative function profile. Use as supporting evidence for level review, not as a replacement for expert judgement.
Item writing Unexpected vocabulary can interfere with the construct being tested. Check stems, keys, options and distractors for unintended lexical difficulty.
Cross-language comparability Equivalent tasks in different languages may not have equivalent lexical demands. Use cross-linguistic data to identify potential comparability problems.
Validation Claims about level, difficulty or usefulness need empirical support. Compare candidate classifications with expert review, learner data and published resources.

11. Cross-linguistic semantics and translation equivalence

The Atlas is explicitly cross-linguistic. This means translation equivalence must be handled carefully. The same concept may be realised as a single word in one language, a multiword expression in another and a construction in a third.

Topic Why it matters for this project Example
Sense alignment Equivalent forms must represent the same sense, not just similar dictionary entries. apply for a job is not the same as apply a rule.
False friends Similar-looking words may differ in meaning, register or usage. A cognate may help recognition but mislead production.
Constructional equivalents Some meanings are naturally expressed by patterns rather than individual words. German sich bewerben and Czech žádat o illustrate why direct English-word translation is insufficient.
Morphological load Production may require gender, case, aspect, agreement or reflexive marking. Productive CEFR may be higher than receptive CEFR in morphologically rich languages.

12. Reproducibility, data governance and audit trail

The project is not only about the final dataset. It is also about making the process transparent enough to audit, repeat and improve.

Topic Why it matters for this project Project practice
Version control Scripts, prompts, taxonomy files and documentation need a change history. Use GitHub for code, prompts, notebooks, taxonomy and site documentation.
Data separation Large, private or restricted data should not be stored in a public repository. Use Google Drive for raw data, interim files, outputs, logs and review workbooks.
Prompt versioning LLM outputs depend on the exact prompt and taxonomy version used. Record prompt text, model name, taxonomy version and output schema.
Review trail Expert changes should be traceable. Keep original candidate labels, expert decisions and adjudication comments.
Validation stages Candidate outputs need later checking against evidence. Separate LLM judgement, expert review and validated evidence fields.
