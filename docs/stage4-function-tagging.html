Stage 4: Function Tagging and Prompt Passes

Run Pass 1, Pass 2 and Pass 3 to generate provisional sentence-level function tags for expert review.

Home Rationale Workflow Technical setup Reviewer area Methodology FAQ Further reading
Purpose: Stage 4 creates provisional sentence-level function tags. It does not create validated CEFR data.

What happens in this stage?

Sentence rows are sent to the OpenAI API through three prompt passes. The model must select function labels only from the controlled taxonomy. Each script appends completed rows to CSV, so a run can be resumed if it stops part-way through.

Pass 2 challenges the Pass 1 label. It should accept Pass 1 if it is defensible, change it only if another label is clearly better, or mark it uncertain.

Implementation note on prompts

Prompt text is embedded directly inside the version-controlled Python scripts in scripts/. The scripts are therefore the canonical, inspectable record of the exact prompt instructions used in each tagging run.

Exact prompt instructions (auto-generated from the scripts)

The instruction text below is extracted directly from the version-controlled scripts in scripts/, so this page always matches the code used in tagging runs. Last extracted: 09 June 2026. At runtime the controlled taxonomy, the sentence and (for Pass 2 and Pass 3) the previous pass output are appended below these instructions, and the model must return a strict JSON object.

Pass 1: first-pass function tagging — exact instruction text (from scripts/run_pass1.py) 
You are annotating ONE sentence for CEFR-derived communicative function.

Do not use memory from any previous examples.
Do not generalise across rows.
Tag what the whole sentence is doing communicatively, not the topic of the sentence.
Use only a function_id from the taxonomy.
Keep the rationale short: maximum 25 words.
If uncertain, use confidence = low and requires_review = true.
If there is no plausible alternative, set alternative_function_id to an empty string.
Pass 2: blind validation — exact instruction text (from scripts/run_pass2.py) 
You are doing BLIND VALIDATION of one sentence-level CEFR-derived function tag.

Your job is to validate the Pass 1 tag carefully.

Do not agree automatically, but do not change the label merely because another label is also possible.

Accept the Pass 1 tag if it is a reasonable and defensible best-fit label.

Change the Pass 1 tag only when another taxonomy label is clearly better for the whole sentence.

Rules:
- Use only a function_id from the controlled taxonomy.
- If Pass 1 is best, validator_decision = accept.
- If another label is better, validator_decision = change.
- If genuinely ambiguous, validator_decision = uncertain and requires_review = true.
- Keep validation_rationale short: maximum 30 words.
- Tag what the whole sentence is doing communicatively.
Pass 3: adjudication — exact instruction text (from scripts/run_pass3.py) 
You are making the final moderated decision for one CEFR-derived sentence-level function tag.

Use the controlled taxonomy only.
Use Pass 1 and Pass 2 as evidence, but decide independently.
If Pass 1 and Pass 2 agree, still check whether the agreed label is genuinely the best whole-sentence function.
If Pass 1 and Pass 2 disagree, choose the label that best captures what the whole sentence is doing communicatively.
Do not simply average the two previous answers.
Keep adjudication_rationale short: maximum 35 words.
Mark human_review_recommended true only if the case remains genuinely ambiguous.

Checks and risks

  • Tag the communicative function of the whole sentence, not the topic of the sentence.
  • Use only valid function IDs from the controlled taxonomy.
  • Do not treat LLM output as evidence of CEFR level.
  • Keep all outputs as provisional Tier 4 candidate material.
  • Watch for rubber-stamping in Pass 2.
