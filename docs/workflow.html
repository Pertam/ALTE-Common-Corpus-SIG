The workflow creates structured candidate annotations for human review.

Workflow overview

Stage 1: Corpus preparation

Document source, licence, language, date and register.

Stage 2: Processing

Tokenise, POS-tag, lemmatise and calculate corpus evidence.

Stage 3: Sampling

Create stable target-occurrence rows.

Stage 4: Lexical-sense tagging

Propose and approve inventories, then label the target lemma sense independently.

Stage 5: Function tagging

Label what the whole sentence is doing using independent taxonomy-based passes.

Stage 6: QA and expert review

Join outputs, review sense and function separately, and aggregate by sense.

The data unit

Each row represents one target lemma occurrence in one corpus sentence:

row_id
language
sentence_id
sentence
target_token
target_lemma
target_pos

If a sentence contains two sampled targets, it appears in two rows with different row IDs.

Parallel annotation after inventory approval

BranchQuestionInput
SenseWhat does the target lemma mean here?Sentence, target occurrence and approved lemma-specific inventory
FunctionWhat is the whole sentence doing?Sentence and controlled function taxonomy

The classifiers do not see one another's labels. Their outputs are combined only after independent annotation.

Human decision points

  1. Approve or revise each lemma-specific sense inventory.
  2. Review disagreements, low-confidence rows, OTHER and UNCLEAR.
  3. Review a random sample of agreements.
  4. Keep human sense and function decisions separate.
  5. Align reviewed language-specific senses to concept IDs only afterwards.
